# 자택 파일럿 하드웨어 현황

> 마지막 갱신: 2026-09-01 · 이 문서는 `namo` 앱 레포의 `docs/hardware-pilot-status.md`에서 이관했습니다.
> 목적: 하드웨어 사실과 미확인 항목을 한곳에 기록합니다. 설계 결정은 `pilot-design.md`, 조립 절차는 `bring-up-guide.md`가 담당합니다.

## 1. 문서 범위

이 문서는 **사실만** 기록합니다. 보유하거나 구매한 하드웨어, 실물에서 확인해야 하는 항목, 확인이 끝난 값을 남깁니다.

설계 판단(핀 배정·안전규칙·프로토콜)은 이 문서에 쓰지 않습니다. 부품을 실측한 결과가 설계와 다르면 이 문서를 먼저 갱신한 뒤 `pilot-design.md`를 고칩니다.

## 2. 작업 경계

| 영역 | 담당 | 이 레포 범위 |
|---|---|---|
| ESP32-S3 펌웨어 | 이 레포 | ✅ BLE 센서 수집, GPIO 입력, 펌프 제어, 로컬 안전규칙, MQTT 발행·구독 |
| 게이트웨이 | 이 레포 | ✅ 맥에서 Mosquitto + Zigbee2MQTT 실행, Aqara 누수센서 수집 |
| 백엔드 HTTP API | 미착수 | ❌ 이번 파일럿 범위 밖 |
| Namo 앱 (Lynx) | 별도 담당자 | ❌ 이번 파일럿 범위 밖 |

Namo 앱은 이 레포의 MQTT 토픽에 직접 연결하지 않습니다. 앱은 후속 백엔드 HTTP API 뒤에만 존재합니다.

| 장비 | 상태 | 비고 |

| 브레드보드 | 보유 | |
| 점퍼선 | 보유 | |
| 인두기 세트·기본 전자작업 도구 | 보유 | |
| USB 웹캠 | 보유 | PC 연결용 일반 웹캠 |
| 맥 (상시 가동 가능) | 보유 | 게이트웨이 호스트로 사용 |

### ESP32-S3 보드 실측 (2026-09-03, `espflash board-info`)

| 항목 | 값 |
|---|---|
| 칩 | esp32s3, revision v0.2 |
| 크리스탈 | 40 MHz |
| 플래시 | 8 MB (내장) |
| PSRAM | **없음** (features에 미표기) |
| 외장 안테나 | **미장착** (IPEX 커넥터 비어 있음) |
| 기능 | WiFi, BLE, Embedded Flash |
| MAC | `14:c1:9f:c4:fc:30` |
| 시리얼 포트 | `/dev/cu.usbmodem21201` (맥) |
| Secure Boot / Flash 암호화 | 둘 다 비활성 |

PSRAM이 없으므로 GPIO33~37에 대한 제약이 없습니다. MAC은 MQTT 클라이언트 ID나 토픽의 장치 식별자로 쓸 수 있습니다.

**안테나가 없어 WiFi를 쓸 수 없습니다** (2026-09-06 확인). 커넥터가 비어 있으면 감도만 떨어지는 것이 아니라 임피던스 부정합으로 신호 대부분이 반사됩니다. 실측:

| 대상 | 거리 | 맥이 받는 세기 | 보드가 받는 세기 |
|---|---|---|---|
| 공유기 `U+NetA349` | 방 건너 | (연결됨) | -91~-93dBm, 3회 중 1회만 스캔에 잡힘 |
| 아이폰 핫스팟 | 30cm | -15dBm | **스캔에 잡히지 않음** |

거리를 좁혀도 해결되지 않습니다. BLE가 동작하는 것과 모순되지 않습니다. BLE는 훨씬 낮은 신호로도 통신하는 규격이고, 대상이 1m 이내였습니다.

## 5. 확인이 필요한 항목

조립 전 실물에서 확인해야 합니다. 확인이 끝나면 `확인값` 칸을 채우고 날짜를 남깁니다.

| # | 항목 | 왜 필요한가 | 확인 방법 | 확인값 |
|---|---|---|---|---|
| H1 | ESP32-S3 보드의 정확한 모델명 | 내장 LED 핀·PSRAM 종류에 따라 사용 금지 GPIO가 달라짐 | 보드 금속 캡 각인 확인, 또는 `espflash board-info` | **확인 (2026-09-06)**. 칩은 ESP32-S3 rev v0.2, 40MHz 크리스탈, 플래시 8MB, MAC `14:c1:9f:c4:fc:30`. 핀 헤더가 `D0`~`D10` 라벨인 소형 보드이며, GPIO 대응은 `pinscan`으로 실측해 `pilot-design.md` §3.1에 적었습니다. 상태 LED로 쓸 핀은 헤더에 없어 생략합니다 |
| H2 | ESP32-S3의 PSRAM이 옥탈인지 | 옥탈(N8R8 등)이면 GPIO33~37을 절대 쓰면 안 됨 | `espflash board-info` 출력의 features | **확인 (2026-09-03)**. features가 `WiFi, BLE, Embedded Flash`뿐이라 PSRAM 미탑재입니다. GPIO33~37을 써도 되며 §3 핀맵을 바꿀 필요가 없습니다 |
| H3 | 펌프에 12V 어댑터가 동봉됐는지 | 없으면 12V 1A 이상 어댑터를 추가 구매해야 함 | 택배 박스 확인 | **확인 (2026-09-06)**. 동봉되지 않았습니다. 집에 있는 어댑터는 9V·19V뿐이라 둘 다 쓸 수 없어 12V를 구매해야 합니다 |
| H4 | 펌프의 실제 소비 전류 | 어댑터 용량 산정. 4.8W면 12V에서 0.4A이나 기동전류는 더 큼 | 멀티미터 전류 측정 | 미확인 |
| H5 | AOD4184 모듈의 단자 라벨과 배열 | 모듈마다 `SIG/GND` 또는 `PWM/GND`, 옵토커플러 유무가 다름 | 모듈 실크스크린 육안 확인 | 미확인 |
| H6 | AOD4184 모듈이 3.3V 게이트로 완전히 켜지는지 | 부분도통이면 MOSFET이 발열하고 펌프가 약하게 돌음 | `bring-up-guide.md` Stage 2 (무부하 전압 측정) | 미확인 |
| H7 | 플로트 스위치의 NO/NC 방향 | 부착 방향에 따라 논리가 반전됨. 반대로 알면 빈 물통에서 펌프가 돌음 | 멀티미터 도통 모드로 뜬 상태/가라앉은 상태 각각 측정 | **확인 (2026-09-07)**. 플로트를 올리면 도통(삐), 내리면 개방. 즉 물 있음 = 도통 = 내부 풀업 기준 GPIO5 LOW. 단선이 `empty`로 읽히는 안전한 방향입니다 |
| H8 | 2m 튜브 실제 양정에서의 유량 | 급수량을 "펌프 N초"로 환산하려면 실측이 필수. 카탈로그 240L/h는 무양정 기준 | `bring-up-guide.md` Stage 4 (계량컵 실측) | 미확인 |
| H9 | HHCC 정확한 모델명과 펌웨어 | HHCCJCY01 계열이어야 passive BLE 파싱이 동작 | Flower Care 앱 또는 BLE 스캔 시 device type 값 | **확인 (2026-09-06)**. device type `0x0098`로 HHCCJCY01 계열이 맞습니다. MAC `5C:85:7E:14:23:64`. 암호화되지 않아 passive scan만으로 네 값을 모두 읽었습니다 |
| H10 | Aqara 누수센서 정확한 모델명 | Zigbee2MQTT 지원 여부와 페어링 방식 확인 | 본체 뒷면 모델번호 (SJCGQ11LM 등) | 미확인 |
| H11 | USB 웹캠 모델과 해상도 | 카메라는 이번 파일럿 후순위지만 기록은 남김 | 맥 `system_profiler SPCameraDataType` | 미확인 |

## 6. 부품별 알려진 특성

조사로 확인한 사실입니다. 실물 확인(§5)과 충돌하면 실물이 우선입니다.

### AOD4184 MOSFET 모듈

- 3.3V 트리거 신호를 지원한다고 표기된 모듈이 일반적입니다. 다만 3.3V는 게이트 구동 여유가 크지 않아 전류를 낮게 쓰는 조건에서만 안전합니다. 이번 펌프는 0.4A 수준이라 여유가 충분합니다.
- **모듈에 플라이백 다이오드가 없습니다.** 펌프 같은 유도성 부하에는 외부 다이오드가 필수입니다. 1N4007을 이 용도로 씁니다.
- 옵토커플러 절연형 변종이 있습니다. 절연형이면 입력이 부하 전압 기준으로 바이어스돼 3.3V든 5V든 동일하게 동작합니다. 어느 쪽인지는 H5에서 확인합니다.

### HHCC Flower Care (HHCCJCY01)

- BLE advertising에 Xiaomi MiBeacon 형식으로 측정값을 실어 보냅니다. 서비스 UUID는 `0xFE95`, 디바이스 타입은 `0x0098`입니다.
- **GATT 연결 없이 passive scan만으로** 흙 수분·온도·조도·전도도 네 값을 모두 얻을 수 있습니다. 한 광고 패킷에는 측정값이 하나만 들어오므로 여러 패킷을 모아야 전체가 채워집니다.
- 배터리 잔량은 advertising에 실리지 않는 펌웨어가 많습니다. 필요하면 GATT 연결이 추가로 필요하며, 이번 파일럿에서는 후순위입니다.

#### 실측 (2026-09-06, `blescan`)

- 광고 주기는 **약 10초**이고, 한 광고에는 측정값이 **하나만** 실립니다.
- 순서는 흙수분 → 전도도 → 온도 → 조도로 순환하므로 **네 값을 모두 채우는 데 약 40초** 걸립니다.
- 프레임 카운터가 광고마다 1씩 증가해, 같은 광고의 재전송을 걸러내는 데 쓸 수 있습니다.
- 관측한 배터리 값은 없었습니다. 위 서술대로 이 펌웨어도 배터리를 광고에 싣지 않는 것으로 보입니다.
- 공기 중에서 흙수분 3%, 전도도 0 µS/cm로 읽혔습니다. 흙에 꽂았을 때의 기준값은 Stage 5에서 따로 잽니다.
- 측정 갱신 주기는 대략 수 분 단위입니다. 실시간 반응을 기대하면 안 됩니다.

### 1N4007

- 역회복 시간이 느린(수십 µs) 일반 정류 다이오드입니다. ON/OFF 스위칭에는 충분하지만 **PWM 구동에는 적합하지 않습니다.** 이번 설계에서 펌프에 PWM을 쓰지 않는 이유입니다.

### SONOFF ZBDongle-E

- EmberZNet(EFR32) 기반입니다. Zigbee2MQTT에서 `ember` 어댑터로 설정합니다. Texas Instruments 기반인 ZBDongle-P와 설정이 다르므로 주의합니다.

## 7. 카메라 계획 (후순위)

이번 파일럿의 필수 범위가 아닙니다. 급수와 센서가 안정된 뒤에 붙입니다.

```text
USB 웹캠 → 상시 가동 맥 → FFmpeg / MediaMTX → 최신 스냅샷 + 촬영시각
```

정지 이미지부터 시작하며 실시간 스트리밍은 하지 않습니다.

## 8. 파일럿 식물

| 항목 | 내용 |
|---|---|
| 식물 | 바질 |
| 구성 | 모종 화분 1개(펌프·HHCC 연결, 시스템 검증용) + 씨앗 화분 1개(수동 급수, 성장 기록용) |
| 선정 이유 | 성장이 빨라 변화가 눈에 보이고, 물이 마르면 잎이 눈에 띄게 처졌다가 급수 후 1시간 내 회복해 **센서값과 별개로 급수 성공을 육안 교차검증**할 수 있습니다. 과습에도 비교적 잘 버팁니다 |

씨앗부터 키우는 화분에 펌프를 연결하지 않는 이유는, 발아기에는 흙을 항상 촉촉하게 유지해야 해서 정량 급수 검증이 불가능하고 과습으로 씨앗이 썩으면 2주를 날리기 때문입니다.
